# نزّلها — حالة التنفيذ والتحقق

## الخلاصة

تقدّم المشروع من commit المرحلة الأولى `c08ce91a99df03e6703de41a80a312d7698886ab` إلى معاينة أوسع بهوية عربية، ومعالجات ملفات عامة، واستئناف HTTP أكثر أمانًا، ومدير ملفات، ورسائل أخطاء عربية وتقارير منقّحة. **نجح 117 اختبارًا، دون فشل أو أخطاء أو اختبارات متجاوزة، ونجح Lint دون أخطاء مانعة.**

لكن التسليم التجريبي النهائي **لم يكتمل ولم يُنشر بعد**: يلزم حسم عدم توافق شهادة Debug الجديدة مع APK القديم، وتوفير مسار رفع GitHub مصادق عليه في بيئة التنفيذ. لا يوجد APK نهائي بعد إصلاحات المراجعة الأخيرة، ولا تُقدَّم نسخة البناء الأقدم كأنها النهائية. كما أن Drive الرسمي واختبارات الجهاز ليست ميزات أو نتائج مكتملة.

## النتائج المثبتة

الحالة البرمجية المختبرة عند `a3b5ef20b16fff5389dfe3ff7f0be7143175c90e`. نجح الأمر الذي يجمع `:app:testGithubPreviewDebugUnitTest` و`:app:lintGithubPreviewDebug` في **3 دقائق و21 ثانية**. [الملخص الآلي](verification/validation-summary.json) يذكر أعداد كل فئة اختبار ونتائج المقارنة.

- **117 اختبارًا، 0 فشل، 0 أخطاء، 0 تجاوز.** بقيت جميع حالات الاختبار الـ95 الموجودة قبل المراجعة، وأضيفت 22 حالة؛ لا توجد حالة سابقة مفقودة في المقارنة.
- **Lint: 0 أخطاء مانعة، 203 تحذيرات، وملاحظة معلوماتية واحدة.** المقارنة المتاحة مع لقطة ما قبل المراجعة في هذه المهمة كانت 205 تحذيرات وملاحظتين؛ ليست هذه مقارنة Lint مستقلة مع commit الأساس الأصلي.
- ظهرت في الجولة الأولى بعد المراجعة مشكلة ترجمة Kotlin في استدعاء `padding` الجديد، قبل تشغيل الاختبارات. أُصلح إلى معاملات Compose الصحيحة، ثم نجحت الجولة التالية كاملة. السجل الفاشل محفوظ محليًا ولا يُخفى.
- جميع مفاتيح `strings.xml` الأساسية القابلة للترجمة لها مقابل عربي، وملفا الموارد صالحان دون مفاتيح مكررة. هذا فحص موارد، وليس ادعاءً بتدقيق بصري على هاتف لكل شاشة موروثة.
- جرى تحليل YAML وفحص Bash لسير عمل CI بنجاح. لم يُشغَّل هذا السير على GitHub بعد؛ نجاح الفحص المحلي لا يُسمّى نجاحًا بعيدًا.

### ما غطّاه HTTP والأمان

غطّت الاختبارات التحويلات واسم RFC 5987، ورفض بيانات الاعتماد ووجهات غير HTTP، وHTML، وبديل HEAD غير المدعوم، وحجمًا مجهولًا عبر chunked، وانقطاع اتصال وإلغاء واستئناف، وETag قوي وLast-Modified، وتغيّر نسخة الخادم، وpartial بلا sidecar، ومدققًا محذوفًا من 206، ونطاق 206 مجهول الحجم الكلي، وحجب عناوين خاصة ومحجوزة. لا يُلحق المحرك استجابة غير موثقة بالبايتات القديمة ولا ينشر partial كملف مكتمل.

اختُبرت إزاحة **3,000,000,000 بايت** بملف sparse لاختبار حسابات Long وRange دون تنزيل غيغابايتات. هذا ليس اختبار سلامة تنزيل حقيقي متعدد الغيغابايتات، ولا قياسًا للذاكرة أو البطارية على Android.

### المصادر التي اختُبرت فعلًا

جرى حل وتنزيل [README عام من فرع Nazelha على GitHub](https://github.com/hoodmoshla/Nazelha/blob/feature/direct-http-downloads-stage1-2026-10-27/README.md) مع تفعيل `NAZELHA_LIVE_HTTP_TESTS=1`. بقية اختبارات النقل تستخدم خادم HTTP محليًا مضبوطًا، وليست تأكيدًا لدعم كل موقع خارجي.

تطبيع روابط GitHub للإصدارات والمرفقات وDropbox اجتاز اختبارات وحدات؛ لم يُجر تنزيل حي لكل فئة منها. معالج Dropbox يتبع [التوثيق الرسمي لـdl=1](https://help.dropbox.com/share/force-download)، ويحافظ على مفاتيح المشاركة دون محاولة تجاوز الصلاحيات. لم تُختبر تنزيلات YouTube أو الفيديو/الصوت وقوائم التشغيل داخل APK على جهاز. تفاصيل [القيود ومتطلبات Drive الرسمي](GOOGLE_DRIVE_RESEARCH.md) محفوظة بوضوح.

### تحذيرات المراجعة الجديدة غير المانعة

ظهرت ست ملاحظات Warning جديدة قياسًا بلقطة ما قبل المراجعة: `PluralsCandidate` لنص حد المسح، و`UnusedResources` لموردي foreground/monochrome القديمين اللذين لم تعُد الأيقونات تشير إليهما، وتحذيرا `UsableSpace` لفحوص المساحة المحافظة، و`IconLauncherShape` لمورد round قديم التوافق بكثافة hdpi. فحص المساحة لا يحتسب cache القابل للإخلاء تلقائيًا، وقد يلزم تفريغ مساحة وإعادة المحاولة. هذه التحذيرات لم تُخفَ أو تُحوَّل إلى نجاح بلا ذكر؛ لا تمنع الترجمة أو الاختبارات، لكنها تبقى ضمن تحسين المعاينة.

## التوقيع: القرار المطلوب قبل توزيع APK

مقارنة الشهادات أثبتت أن APK المرحلة الأولى المنسوخ من المصدر القديم يحمل شهادة مختلفة عن Debug المحلي. [المقارنة الدقيقة للبصمتين](verification/signing-comparison.json) عامة ولا تتضمن أي مفتاح خاص.

بما أن الحزمة هي نفسها `com.snapnet.preview.debug`، **لن يقبل Android النسخة الموقعة بالمفتاح الجديد كتحديث فوق APK القديم**. لم يُنسخ مفتاح المرحلة الأولى، ولم يُستعمل أو يُرفع مفتاح إصدار SnapNet. لم يُحذف أي تطبيق أو أي بيانات من جهاز المستخدم.

يمكن اعتماد Debug المستقل المطلوب كتجربة غير متوافقة مع ترقية القديم، أو طلب توافق التحديث الذي يتطلب مفتاح المرحلة الأولى الصحيح والتحقق من هويته. لا يُنشر APK بتوقيع بديل على أنه تحديث متوافق، ولا تُحذف النسخة القديمة لتجاوز التعارض تلقائيًا.

## الرفع واستقلال المستودع

كل العمل داخل نسخة `hoodmoshla/Nazelha` وعلى الفرع التجريبي المحدد. حُفظت التعديلات في commits محلية واضحة، دون Force Push أو تغيير `main` أو Tags أو Releases أو مستودع SnapNet. حُفظ GPL v3 وسجل الأصل. السجلات المؤقتة وملفات البناء والمفاتيح مستبعدة من Git.

اتصال GitHub القائم ظهر مفعّلًا إداريًا، لكن بيئة التنفيذ لم تحصل منه على وسيلة كتابة مصادق عليها: فشل `git push --dry-run` بسبب `could not read Username`، والمتصفح لم يوفّر جلسة GitHub مسجلة. لا يُبنى هذا الاستنتاج على غياب سر محفوظ وحده. لم يُنشأ رمز أو يُطلب توسيع صلاحيات تلقائيًا. يلزم استعمال اتصال مصادق متاح للمنسق، أو اعتماد مناسب يقدمه المستخدم، قبل ادعاء رفع commits.

## إكمال التسليم دون إعادة الاختبارات بلا داعٍ

بعد حسم التوقيع واعتماد الرفع: افحص أن الفرع البعيد لم يتقدم، وارفع دون Force Push إلى الفرع نفسه، ثم نفّذ بناء ARM64 واحدًا وافحص الحزمة والاسم وموارد الأيقونة والـABI والتوقيع الفعلي وبصمة الملف وحجمه. حدّث التقرير ورابط التنزيل بالمخرجات الحقيقية فقط. لا تستلزم إضافة الوثائق وحدها إعادة مجموعة JVM الناجحة؛ أي تغيير برمجي جديد يستلزم التحقق الملائم له. أوامر إعادة الإنتاج في [README](../README.md).
