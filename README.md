# نزّلها — فيديو وملفات

تطبيق Android تجريبي عربي لتنزيل الفيديو والصوت والملفات وإدارة المهام والملفات المحفوظة. انطلق العمل من الفرع `feature/direct-http-downloads-stage1-2026-10-27` عند `c08ce91a99df03e6703de41a80a312d7698886ab` دون تعديل مستودع SnapNet أو فروعه أو إصداراته.

## ما نُفّذ

- الاسم **«نزّلها — فيديو وملفات»** وأيقونات قياسية ودائرية وتكيفية وأحادية اللون. العربية هي البداية الافتراضية مع احترام اختيار المستخدم السابق وRTL. الحزمة التجريبية ثابتة: `com.snapnet.preview.debug`؛ كما عُزل معرّف الأساس لبقية متغيرات البناء عن `com.snapnet` الأصلي.
- تنزيل HTTP/HTTPS المباشر عبر HEAD أو فحص نطاق صغير، واستخراج الاسم والنوع والحجم، والتحويلات الآمنة وحجب عناوين الشبكة الخاصة والمحجوزة. لا يضيف هذا المسار Cookies أو ترويسات مصادقة ولا يقبل بيانات اعتماد داخل URL.
- تطبيع روابط GitHub العامة وملفات `blob` والإصدارات والمرفقات، ومعالج مستقل لروابط مشاركة Dropbox العامة باستخدام `dl=1` وفق [توثيق Dropbox](https://help.dropbox.com/share/force-download). اختبار التطبيع لا يساوي إثبات تنزيل حي من كل خدمة؛ المصادر المختبرة فعليًا مذكورة في سجل التحقق.
- طابور موحد قائم للفيديو والصوت والملفات، وإيقاف/استئناف/إلغاء وإعادة محاولة يدوية، وحد تزامن قابل للضبط من 1 إلى 5 (الافتراضي 3). تبقى مسارات `yt-dlp` الحالية للفيديو والصوت وقوائم التشغيل دون استبدال.
- استئناف HTTP مربوط بمدقق **استجابة GET التي كتبت البايتات**، لا ببيانات HEAD الجديدة. تُحفظ ملكية مبهمة وETag قوي أو Last-Modified في sidecar مخفي بجوار partial، بلا URL أو رمز وصول. يتطلب الإلحاق استجابة 206 ونطاقًا ومدققًا متوافقين؛ خلاف ذلك يبدأ من الصفر بأمان وبمحاولة رجوع محدودة. الملفات القديمة ذات أسماء hashCode غير الموثقة لا تُرحّل ولا تُحذف تلقائيًا.
- نشر الملف النهائي باسم متاح بدل الكتابة فوق ملف سابق، وفحص مبدئي للمساحة المحلية عند معرفة الحجم، مع إبقاء partial عند فشل النقل أو النشر. أحجام غير معروفة أو حصص مزود SAF تظل معتمدة على أخطاء نظام الملفات الفعلية.
- شاشة **الملفات**: بحث وتصنيف وفرز واسم وحجم وتاريخ وحالة ومجلد، ثم فتح ومشاركة وإعادة تسمية وحذف مؤكد يوضح الموقع. تدعم طلب إذن التخزين القديم وإعداد إدارة الملفات الحديث. يقتصر SAF على ملفات مجلد الوجهة المباشرة، لا مجلداته الفرعية غير المرتبطة. يجري المسح والفرز خارج خيط الواجهة، مع حد معلن 10,000 ملف/20,000 مدخل لحماية الأداء. لا تُفتح الملفات أو تُثبّت تلقائيًا.
- رسائل عربية للمصادقة وCAPTCHA و403 المحايد والملفات غير المتاحة/المنتهية وانقطاع الشبكة ونفاد المساحة، مع تنقيح التقارير المنسوخة من بيانات الاعتماد وقيم استعلام URL.

## الحدود الصريحة

**Google Drive غير مدمج رسميًا في هذا البناء.** لا يوجد إعداد OAuth/API أو حساب اختبار مرتبط بالحزمة التجريبية. الملفات الخاصة تحتاج تفويضًا صحيحًا، ولا نعوّض ذلك بتجاوز الحماية. راجع [متطلبات Drive الرسمية](docs/GOOGLE_DRIVE_RESEARCH.md).

صفحات HTML تواصل إلى المواقع وعمليات الاستخراج التي يدعمها `yt-dlp` فعليًا؛ لا يوجد زاحف عام لكل روابط الويب. دُرس المتصفح المدمج ولم يُضف في هذه المعاينة لتجنب توسيع سطح Cookies والجلسات؛ يمكن مشاركة الرابط من المتصفح الخارجي. لا يضمن التطبيق تجديد الروابط المؤقتة أو تجاوز DRM أو CAPTCHA أو صلاحيات المصدر.

يحفظ المحرك المهام غير المكتملة في MMKV ويستعيدها عند فتح التطبيق؛ لا يوجد بدء تلقائي عند إقلاع Android. لا يتوفر هاتف أو محاكي متصل في بيئة التحقق، لذلك لم تُثبت عمليًا استعادة العملية بعد إعادة تشغيل الهاتف، أو سلوك الخلفية والإشعارات والبطارية أو تنزيلات الفيديو/الصوت داخل APK. الاختبارات والسياسات البرمجية لا تحل محل اختبارات الجهاز.

نُقلت التفضيلات الافتراضية القديمة من `Downloads/SnapNet` إلى `Downloads/Nazelha` دون نقل الملفات القديمة أو حذفها. يمكن اختيار مجلداتها القديمة يدويًا إذا لزم عرضها.

## التوقيع والتثبيت

البناء التجريبي يستخدم Debug المحلي، ولا يستعمل مفاتيح Release الموروثة أو يضعها في المستودع. **شهادة Debug الحالية تختلف عن APK المرحلة الأولى المنسوخ من المصدر القديم؛ لذلك ليست ترقية متوافقة معه رغم تطابق الحزمة.** لا تحذف نسخة مثبتة أو بياناتها قبل حفظ ما تحتاجه. تسليم APK النهائي متوقف على حسم هذا الاختيار والتحقق من الأثر النهائي؛ لا يدّعي هذا الفرع توافق التوقيع مع APK القديم.

مفتاح Debug على مشغّل GitHub Actions المؤقت قد يختلف أيضًا عن المفتاح المحلي، فلا تُعامل آثار CI كتحديثات متوافقة تلقائيًا. ليست هذه منظومة توقيع إصدار إنتاجي.

## البناء وإعادة الاختبار

المتطلبات: JDK 21 وAndroid SDK 35. بناء APK معاينة ARM64:

```bash
ANDROID_HOME="$HOME/Android/Sdk" \
ANDROID_SDK_ROOT="$HOME/Android/Sdk" \
./gradlew :app:assembleGithubPreviewDebug \
  -PnoSplits -PABI_FILTERS=arm64-v8a --no-daemon
```

تشغيل اختبارات الوحدات وLint والبناء في جلسة واحدة، عند اعتماد توقيع المعاينة:

```bash
ANDROID_HOME="$HOME/Android/Sdk" \
ANDROID_SDK_ROOT="$HOME/Android/Sdk" \
NAZELHA_LIVE_HTTP_TESTS=1 \
./gradlew :app:testGithubPreviewDebugUnitTest \
  :app:lintGithubPreviewDebug :app:assembleGithubPreviewDebug \
  -PnoSplits -PABI_FILTERS=arm64-v8a \
  --no-daemon --no-configuration-cache
```

متغير `NAZELHA_LIVE_HTTP_TESTS=1` يفعّل اختبار تنزيل محدود لرابط GitHub عام؛ بقية اختبارات HTTP تستخدم خادمًا محليًا. يتحقق [GitHub Actions](.github/workflows/nazelha-validation.yml) من الاختبارات وLint والحزمة والاسم وARM64 والتوقيع والبصمة قبل الاحتفاظ بالأثر 14 يومًا، دون إنشاء Tag أو Release. تشغيله البعيد لا يُعد ناجحًا إلا بعد رفع الفرع ورؤية نتيجته الفعلية.
